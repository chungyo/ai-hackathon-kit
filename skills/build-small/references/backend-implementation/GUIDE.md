# 백엔드 구현

과제의 입력·처리·결과와 데이터 상태를 실제 계약에 맞게 구현한다. 시험 규정과 과제 README가 우선이며 제공된 서버·프레임워크·저장소·테스트 방식을 먼저 사용한다. 새 인프라, 외부 서비스, 개인 API 키를 임의로 도입하지 않는다.

1. 관련 라우트·핸들러·서비스·저장소와 기존 테스트, 실행 방법을 확인한다. 각 필수 기능의 요청/응답, 필드와 타입, 상태 코드, 데이터 저장 여부와 오류 계약을 제공 자료에서 찾는다. 없는 비즈니스 정책·인증 조건은 임의 확정하지 않고 확인 필요로 남긴다.
2. 외부 입력은 기존 체계에 맞춰 타입·필수값·허용 범위와 해당 업무 규칙을 검증한다. 실제로 요구되거나 기존 시스템에 있는 인증·인가와 접근 경계를 보존한다. 없는 로그인 시스템을 임의로 만들지 않는다.
3. 핵심 경로를 입력 → 검증 → 처리 → 저장 또는 응답까지 연결한다. 여러 쓰기가 함께 성공해야 하는 경우 기존 DB가 제공하는 트랜잭션과 실패 시 롤백을 고려한다. 중복 요청·재시도·상태 전이가 데이터에 영향을 주는 기능이면 그 동작을 확인한다. 필요 없는 구조 분리나 대규모 마이그레이션은 피한다.
   - 저장 전후 불변 조건과 변경 대상의 범위를 명시한다. 중복·동시 요청이 중요하면 조회 후 생성만으로 경쟁을 막을 수 있다고 가정하지 말고 기존 고유 제약·트랜잭션과 충돌 응답을 확인한다. 과제가 정하지 않은 중복 정책은 질문한다.
4. DB·외부 의존성 오류를 삼켜 성공으로 돌려주지 않는다. 과제가 허용하고 제공한 연동만 사용하며, 실패 시 안전한 오류와 복구 가능성을 구분한다. 비밀번호·키·개인정보·과제 데이터를 불필요하게 로그나 외부 서비스로 보내지 않는다. 네트워크·권한 제한을 우회하지 않는다.
5. 관련 정상·잘못된 입력·없음·실패와 중요한 경계 조건을 기존 테스트나 허용된 로컬 실행으로 확인한다. 저장 기능은 응답뿐 아니라 실제 상태 변경 또는 미변경도 확인한다. 외부 연동이 불가능하면 mock과 실제 연동 검증을 분리하고 필수 요구 충족을 가장하지 않는다. 실패했던 검증은 수정 후 같은 조건으로 재실행한다.
   - 저장 실패를 시험하려면 입력 검증 등을 통과하도록 유효 요청을 준비하고 안전한 격리 환경에서 실패 경로까지 도달했는지 확인한다. 타임아웃 후에는 서버에 저장됐는지 불명확할 수 있으므로 무작정 재시도하지 않는다.
6. FE가 있으면 실제 FE가 사용하는 경로·필드·오류 계약과 대조한다. 결과 보고에는 실행 명령과 관찰 결과, 미구현·미검증과 제한을 표시한다. 배포·외부 전송은 하지 않는다.

각 기능 단위를 마친 후 `build-small`의 기능별 설명 형식으로 입력→검증→처리→저장/응답, 선택 이유, 실제 테스트 입력·관측과 남은 한계를 사용자에게 설명한다. DB·API 실제 연결과 mock 확인을 구분하고 다른 스킬과 중복 보고하지 않는다.

입력 경계·상태 전이·저장 정합성·실패와 중복 요청의 판단에는 [BE 구현 결정표](references/IMPLEMENTATION.md)를 읽는다. 실제 확인과 미검증 구분은 `verify-and-fix`에 연결한다.

과제가 Next.js App Router를 사용한다면 [Next.js 백엔드 가이드](references/NEXT_APP_ROUTER.md)를 읽는다. Route Handler·서버 처리 선택, 버전 확인, 검증 가능한 요청 처리 예제, 저장·연동·오류 진단과 테스트 방법을 제공한다. Pages Router나 다른 프레임워크에는 강제하지 않는다.

제공 데이터의 검증·적용·재계산·저장 흐름이 중요하거나 사용자가 백엔드 동작을 이해해야 한다면 [Next.js 데이터 처리와 저장 흐름](references/NEXT_DATA_WORKFLOW.md)을 추가로 읽는다. 작은 SQLite 학습 예제와 실제 검증 수준의 구분을 포함한다. 실제 과제의 데이터·인증·출력 계약을 대체하지 않는다.

과제가 FastAPI를 사용한다면 [FastAPI 백엔드 가이드](references/FASTAPI.md)를 읽는다. 실제 버전·설정·계약을 우선하며 요청 검증, DB 세션, 상태·동시성, FE 연결, 테스트와 실행을 해당 요구에 맞게 선택한다.
