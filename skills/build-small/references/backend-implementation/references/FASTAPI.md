# FastAPI 백엔드 구현과 검증

FastAPI를 선택한 과제에서만 사용한다. 제공된 코드·Python/FastAPI/Pydantic 버전·계약과 시험 규정이 우선이다. 네트워크·패키지 설치를 가정하거나 외부 API를 추가하지 않는다. 다음은 작업 판단표이며 그대로 복사하는 완성 앱이 아니다.

## 1. 시작과 계약

1. 기존 실행 명령, 의존성, 엔트리포인트, API 라우터, DB 초기화 방법, 환경변수, 테스트와 데이터 형식을 확인한다. 문서의 명령은 실제 환경에서 확인한다.
2. 각 API의 method·경로, 필수 입력, 단위·허용 범위, 성공/실패 응답, 인증·인가, 저장 상태를 제공 계약이나 담당자 답변에 연결한다. 경로·상태 코드가 주어지지 않았다면 설계 결정으로 표시한다.
3. Pydantic 모델로 입력 타입·필수값을 확인하고 업무 정책은 별도 처리에서 검증한다. FastAPI의 기본 검증 응답을 사용해도 되는지 과제의 오류 형식과 맞춰 본다. 응답 모델은 반환 범위를 제한하되 인증·인가를 대신하지 않는다.

## 2. DB·정합성·인증

- 기존 DB 라이브러리와 세션 관리 방식을 따른다. SQLModel, SQLAlchemy 등은 과제에서 사용 가능하고 적합한 경우에만 선택한다. 요청 단위의 세션 생성·종료, commit·rollback, 실제 예외 응답을 확인한다.
- 여러 쓰기가 함께 성공해야 한다면 DB 트랜잭션으로 묶고 오류 시 전후 상태를 확인한다. 동시 중복은 트랜잭션이라는 단어만으로 해결되지 않는다. DB의 유니크 제약·조건부 갱신·잠금 등 실제 불변 조건에 맞는 방법과 DB 동작을 확인한다.
- 데이터셋 변경과 계산 결과의 관계가 중요한 경우 계산 당시 입력 버전을 저장하고 오래된 결과가 현재 결과로 표시되지 않는지 확인한다. 조건 확인과 갱신 사이의 경합이 가능하면 DB가 보장하는 원자적 방법을 사용하고 실제 경합 조건을 재현한다.
- 로그인과 권한이 요구되면 비밀번호를 평문으로 보관하지 않고 서버의 각 보호 경로에서 세션과 권한을 확인한다. 비밀값을 환경변수 등 과제에서 정한 경로로 주입하고 응답·로그로 내보내지 않는다. 테스트 계정·초기화 방식은 요구와 환경에 맞춘다.

## 3. React 연결·오류·시간이 오래 걸리는 작업

- FE가 호출하는 실제 base URL, method, body, 응답·오류 필드와 단위를 대조한다. 브라우저에서 서로 다른 origin을 사용하면 필요한 origin·method·headers와 쿠키 자격 증명을 정확히 설정한다. 같은 origin 구성에서는 CORS가 반드시 필요한 것은 아니다. 무조건 전체 허용하지 않는다.
- 입력 오류, 미인증, 권한 부족, 대상 없음, DB 오류를 과제 계약에 맞게 구분한다. 오류를 잡아서 성공 응답이나 빈 데이터로 바꾸지 않는다. 타임아웃은 저장 실패를 뜻하지 않을 수 있으므로 재조회하고 중복 재시도를 주의한다.
- 일반 `def`/`async def`와 DB 드라이버의 동작을 확인한다. CPU 중심의 긴 계산은 `async`나 FastAPI 선택만으로 해결되지 않는다. 실제 데이터로 실행 시간을 측정하고 필요한 경우 과제·환경에서 허용하는 처리 방식을 선택한다. `BackgroundTasks`는 작업 내구성이나 외부 작업 큐를 자동으로 제공하지 않는다.

## 4. 로컬 테스트·실행

1. 정상·무효 입력, 요구된 권한, 중요한 실패를 테스트한다. TestClient 테스트가 실제 서버 네트워크·브라우저 검증은 아니다. 의존성 override는 격리된 저장소 등에서 사용하고, 테스트 종료 시 원상 복구한다.
2. 안전한 테스트 DB를 사용해 저장 전후와 별도 재조회를 확인한다. 입력 검증 실패 테스트는 DB 실패 경로 실행의 증거가 아니다. 실제 DB 연결 또는 재시작 검증은 해당 수준에서 따로 수행한다.
3. 서버 실행 후 헬스체크·실제 API 요청과 FE 연결을 확인한다. Docker가 요구되면 요구된 방식으로 빌드·실행하고 빈 DB 초기화, 설정 주입, DB 파일의 영구 볼륨과 재시작 후 상태를 확인한다. 빌드 성공만으로 재시작 후 데이터 보존을 주장하지 않는다.
4. `HOW_TO_RUN` 등 과제가 지정한 문서에 실제 실행 방법, 필요한 환경변수 이름, 테스트 방법과 미검증을 기록한다. 후속 서술형의 AI 사용 제한을 따른다.
