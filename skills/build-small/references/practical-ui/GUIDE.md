# 실제 업무에 맞는 UI

화면의 목적과 기능을 먼저 완성한다. 시각 스타일은 기존 제품·과제 요구를 우선하며, 모바일 전용 구성이나 특정 브랜드의 색을 일률적으로 강제하지 않는다.

1. 기존 화면, 컴포넌트, 스타일과 과제에 명시된 사용자·주요 행동·데이터를 먼저 확인한다. 없는 요구나 업무 정책을 만들지 않는다.
2. 핵심 사용자 흐름의 시작, 필요한 입력·판단, 결과를 실제 동작으로 연결한다. 버튼·탭·링크는 가능한 행동과 결과가 일치해야 한다. 화면마다 사용자가 지금 알아야 할 정보와 다음 행동의 우선순위를 분명하게 한다.
3. 해당 흐름에 필요한 로딩·빈 결과·유효성 오류·실패·완료 상태를 처리한다. 오류는 가능한 한 관련 입력 가까이에 이유와 복구 방법을 표시하고, 실패 시 사용자의 입력을 불필요하게 잃지 않도록 한다. 과제에서 요구하지 않은 상태나 추가 화면은 강제로 만들지 않는다.
4. 한국어 텍스트는 명확하고 짧게 작성하되 도메인 용어와 기존 톤을 존중한다. 긴 문구·숫자·작은 화면에서 잘림이나 가려짐을 점검한다. 예시 데이터는 예시임을 표시하고 실제 사실로 가장하지 않는다.
5. 의미 있는 요소를 사용하고, 이름 없는 아이콘 버튼, 보이지 않는 포커스, 색상만으로 구분하는 상태를 피한다. 명도 대비와 키보드 동작은 확인할 수 있는 범위에서 점검하고, 측정하지 않았다면 접근성 준수를 단정하지 않는다.
6. 제공된 미리보기에서 응시자가 직접 중요한 화면과 동작을 확인한다. 실제 확인이 불가능하면 코드상 검토와 화면 검증을 구분한다. 외부 이미지 검색·업로드, 화면 캡처 자동화, Computer Use, 외부 AI 모델은 사용하지 않는다.

k-style-ui-ux에서 참고한 핵심은 화면 흐름의 시작과 결과, 동작 가능한 조작, 상태별 복구, 화면 간 사실 일관성이다. 자체 문서로 재구성했으며 원본의 이미지 검색·모델 지정·자동화 및 고정 스타일을 실행하지 않는다.

구현하거나 시각적 결정을 해야 할 때 [UI 가이드](references/UI_GUIDE.md)를 읽는다. 화면 유형별 구조, 기존 시스템이 없을 때의 색·간격·글자 예시, 폼·오류·반응형 검수 기준이 있다. 기존 디자인과 실제 과제 조건이 우선이다.
