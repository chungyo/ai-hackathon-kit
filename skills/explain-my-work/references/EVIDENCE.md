# 판단·검증 근거 기록

이 표는 과제 풀이 중 자신의 이해와 실제 근거를 정리하기 위한 참고다. 과제에서 지정한 문서·형식과 시험의 자료 접근·AI 사용 규칙이 우선이다. 기존 PRD·작업표·필수 제출 문서에 이미 있는 정보는 다시 쓰지 말고 그 위치를 연결한다. 정리된 자료를 후속 서술형에서 열람·복사하거나 AI를 사용할 수 있다고 가정하지 않는다.

## 작업하면서 한 줄씩 연결

| 시점 | 남길 실제 사실 | 연결할 근거 |
| --- | --- | --- |
| 요구 확인 | 요구 ID, 원문·담당자 답변, 필수 조건과 미확정 | 읽은 자료의 실제 위치·답변 |
| 설계 선택 | 선택·실제 고려한 대안·이유·한계; 조건 변경 시 영향 | 과제 조건, 사용 가능한 환경, 결정의 출처 |
| 구현 | 대표 입력→처리→저장/출력과 각 경계의 실제 책임·상태 | 존재하는 파일·함수·API·저장 위치 |
| 검증 | 전제·입력·기대 근거·실제 명령/조작·관측·실행 환경 | 실제 테스트·결과 위치, 확인 수준 |
| AI 협업 | 실제 제안과 실제 수용·수정·기각, 사용자 판단과 확인 | 대화·코드·실행 결과 등 확인한 기록 |

모든 기능이나 모든 범주를 억지로 채우지 않는다. 문서 작성에 구현·테스트 시간을 소진하지 않도록 가장 중요한 사례부터 남긴다. 사용자의 선택인지, AI의 제안인지 기록으로 확인되지 않으면 `판단 주체 확인 필요`로 둔다. 본 적 없는 대안·답변·테스트·성과는 만들지 않는다. 과제 내용·개인정보·비밀값을 외부로 전송하거나 불필요하게 복사하지 않는다.

## 재현과 검증의 경계

- 테스트 코드가 존재하는 것, 테스트가 실제 실행된 것, 실제 DB/API/화면/컨테이너가 확인된 것은 별개의 근거다. mock의 범위 밖은 미검증이다.
- 재현 절차는 실행 당시의 입력·전제, 실제 명령 또는 사용자 조작, 기대 결과의 출처, 관측값과 확인 수준을 포함한다. 명령에 자격증명·민감 정보가 있다면 값이 아닌 안전한 변수명이나 수동 절차만 남긴다.
- 생성 결과를 검증할 때 가능한 범위에서 원문·확인된 정책 또는 사람이 계산한 작은 사례로 기대값을 정한다. 생성기와 검증기가 공유하는 가정을 표시한다. 검증기가 검사하지 않는 조건과 테스트하지 않은 변경 데이터·경계도 함께 기록한다.
- 코드·입력·설정이 바뀌면 기존 결과가 새 상태를 증명한다고 가정하지 않는다. 같은 조건의 재검증 결과 또는 미검증을 표시한다.

## 자신이 설명할 내용

실제 사실에 근거해 `필수 제약과 비교 기준 / 선택과 대안·한계 / 사용자 입력부터 결과까지의 책임과 상태 / 실패·조건 변경 시 동작 / 재현·검증 범위 / AI 제안과 본인의 판단`을 정리한다. 모르는 것은 확인 필요로 표시한다. 과제 풀이 중 이해 확인에만 활용하고 후속 서술형은 해당 시험 규정에 따른다.
