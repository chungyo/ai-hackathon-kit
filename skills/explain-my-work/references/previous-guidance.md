# 구현과 판단을 이해하기

과제 풀이 중에만 사용한다. 후속 서술형에서는 AI 사용과 복사·붙여넣기가 금지된다. 이 스킬은 예상 답안을 대리 작성하거나 외우게 하는 대신, 응시자가 자신이 만든 결과를 이해하도록 돕는다.

1. README와 실제 코드·실행 결과를 바탕으로 목적, 필수 기능과 현재 상태를 요약한다. 수행하지 않은 작업과 추정은 분리한다.
2. 대표 사용자 행동 하나를 골라 입력 위치 → 핵심 처리·분기 → 결과 표시 또는 저장 위치를 실제 파일·함수와 연결해 설명한다. 근거가 없는 이름이나 동작을 만들지 않는다.
3. 중요한 선택에 대해 `문제와 조건 → 선택 → 근거 또는 대안 → 검증 근거 → 제한`을 정리한다. 과제 요구와 충돌하는 가정·미구현은 명확히 밝힌다.
4. 오류·빈 값·외부 연결 실패가 실제로 어떻게 처리되는지 확인한다. 확인되지 않은 경로는 확인 필요로 남긴다.
5. 응시자가 직접 설명해 볼 수 있도록 구현에 맞는 연습 질문을 제안하되, 풀이 시간 내에만 사용한다. 실제 후속 질문을 안다고 주장하지 않는다. 답변은 확인된 사실만으로 응시자가 직접 구성한다.

과제 수행 중 기록할 결정·구현 흐름·검증 근거의 최소 항목은 [판단·검증 근거 기록](EVIDENCE.md)을 참조한다. 시험에서 지정한 파일과 양식이 우선이며, AI 제안과 사용자의 수용·수정·기각은 실제로 확인된 내용만 기록한다. 실제 검증과 계획, 과제 풀이와 후속 서술형을 구분한다.

기능 구현 직후의 짧은 설명은 `build-small`의 기능별 설명 형식을 따른다. 사용자가 이해한 것으로 가정하지 말고, 필요하거나 요청받으면 구체적인 예시나 한 가지 확인 질문으로 추가 설명한다. 정답을 암기시키거나 사용자 답변을 받기 전 이해 완료로 판정하지 않는다.

서술형 이해 점검을 요청하거나 과제 제출 전 설명 준비가 필요할 때 [질문 유형별 확인과 학습](ESSAY_PREP.md)을 읽는다. 실제 원문·구현·실행 기록에 맞는 질문 유형만 우선하고 남은 시간에 맞춰 깊이를 조정한다. 확인한 코드·동작·재현 근거와 확인하지 못한 것을 나누고, 응시자가 자신의 말로 설명해 보도록 돕는다. 후속 서술형이 시작된 뒤에는 시험의 AI·자료 사용 규정이 우선한다.

짧은 확인 항목: 왜 필요한가? 어디에서 실행되는가? 입력과 결과는 무엇인가? 실패하면 어떻게 되는가? 무엇을 직접 확인했고 무엇은 미검증인가?

## 스스로 설명할 수 있는지 확인

과제 풀이 중에만 핵심 흐름 하나를 선택하고 파일과 실제 결과를 보면서 아래를 본인 말로 설명한다.

| 질문 | 찾아볼 근거 |
| --- | --- |
| 왜 이 기능을 먼저 구현했는가? | README 필수 요건·실무자 답변·우선순위 |
| 어떤 입력이 어디를 거쳐 어떤 결과가 되는가? | 입력 컴포넌트·요청 경로·서버 처리·저장/응답 |
| 상태의 최종 기준은 어디에 있는가? | 실제 화면 상태, 서버 판단, 저장 데이터와 코드 위치 |
| 조건이 바뀌면 결과가 어떻게 달라지는가? | 실제 재계산·경계 사례, 미실행 조건과 영향 |
| 검증기가 무엇을 확인하지 못하는가? | 검증 조건·기준 입력·공유 가정·미검증 |
| 실패하면 무엇이 남고 무엇이 표시되는가? | 오류 분기·실제 재현 결과·DB 상태 |
| 어떻게 확인했으며 무엇은 확인하지 못했는가? | 실제 명령 결과·수동 확인 조건·미검증 사유 |

연습 질문에 대한 답은 과제 수행 중 본인이 이해를 점검하는 데 사용한다. 후속 서술형이 시작된 이후에는 이 스킬을 실행하거나 AI 도움을 받지 않는다.
