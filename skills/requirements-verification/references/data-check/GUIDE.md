# 데이터 확인과 계산 검증

원본의 사실, 전처리 결과, 해석을 분리한다. 데이터에 없는 값이나 성능을 만들어 내지 않는다.

1. 제공된 파일의 형식·스키마·행 수·타입·단위와 필수 필드를 확인한다. 개인정보나 문제 내용을 외부로 전송하지 않는다.
2. 과제에 필요한 범위에서 결측·중복·불가능한 값·시간 범위·식별자 관계를 확인한다. 원본을 수정하거나 삭제하기 전에 과제 요구와 영향부터 확인한다. 전처리는 가능하면 별도 결과로 남긴다.
   - 관찰된 값의 업무 의미나 적용 정책이 불명확하면 파일·열·관찰 범위와 영향을 기록하고 `discover-and-decide`의 담당자 질문에 넘긴다. 샘플만 확인했으면 전체 데이터의 현상이라고 단정하지 않는다.
3. 지표의 분자·분모·필터·단위·기간을 확인한다. 대표 행이나 작은 예시로 독립 계산해 집계와 비교하고, 표본만 확인했다면 전체 검증이라고 말하지 않는다.
4. 학습 모델이 실제 요구될 때만 학습·검증 분리, 시간/집단 단위 누수, 전처리의 학습 데이터 기준 적용과 평가 지표를 확인한다. 시험이 요구하지 않는 모델 학습이나 외부 AI 연결을 추가하지 않는다.
5. 결과와 출처, 가정, 수행한 검증, 누락·미검증을 보고한다. 실제 데이터가 부족하거나 연결되지 않으면 그 한계를 드러내고 대체 데이터를 실제 결과인 것처럼 제시하지 않는다.

Next.js App Router에서 실제 데이터셋 적용·재계산·저장을 구현해야 한다면 `backend-implementation`의 [데이터 처리와 저장 흐름](../../../build-small/references/backend-implementation/references/NEXT_DATA_WORKFLOW.md)과 함께 사용한다. 데이터 분석 결과와 DB·HTTP·화면에서의 검증은 별도로 기록한다.

## 빠른 점검표

| 확인 대상 | 질문 | 흔한 오류 |
| --- | --- | --- |
| 날짜·단위 | 기간 경계와 시간대, ms/초·원/천원이 일치하나? | 서로 다른 단위를 그대로 합산 |
| 누락·중복 | 비어 있는 값과 동일 ID는 어떤 의미인가? | 결측을 설명 없이 0으로 채움 |
| 비율 | 분자·분모·대상 필터가 같은 기준인가? | 0인 분모 또는 다른 기간을 사용 |
| 학습 분리 | 전처리가 검증 데이터 정보를 사용했나? | 전체 데이터로 먼저 정규화 |

예: 2건 중 1건이 결측이면 `평균=관측된 값 하나`라는 결과는 결측 처리 정책을 밝힌 경우에만 의미가 있다. 결측을 0으로 넣거나 해당 행을 지우는 정책은 과제에 근거가 없으면 가정이다.
