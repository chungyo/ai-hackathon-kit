# 핵심 흐름 검증표

전체 테스트를 기계적으로 늘리지 말고 과제의 가장 중요한 사용자 행동·데이터 변경·실패 경계부터 선택한다.

| 대상 | 정상 | 빈/잘못된 입력 | 실패·경계 | 확인 증거 |
| --- | --- | --- | --- | --- |
| 화면 입력 | 제출 후 실제 결과 표시 | 필드 오류와 입력 유지 | 처리 중 중복 클릭, 실패 후 재시도 | 제공된 미리보기 수동 확인 + 요청/응답 |
| 조회 | 제공 데이터 목록/상세 | 0건과 잘못된 필터 | 서버 오류와 0건 구분 | 응답·화면 결과 |
| 저장 API | 성공 후 상태 변화 | 필수 누락·타입 | 저장 실패·중복·권한(해당 시) | 응답과 DB 상태 |
| 집계 | 대표 행 직접 계산과 비교 | 결측·단위 불일치 | 분모 0, 기간 경계 | 식·입력과 계산 결과 |

## 실패 복구

1. 입력·기대 결과·실제 결과·오류 위치를 기록한다. 재현 불가능하면 환경과 미확인을 표시한다.
2. 화면 → 요청 → 서버 → 저장 중 관측 가능한 경계를 따라 원인을 좁힌다. 시크릿과 과제 데이터를 외부로 보내지 않는다.
3. 한 가지 가설을 작은 변경으로 확인한다. 테스트를 통과시키기 위해 요구사항·기대값을 임의로 낮추지 않는다.
4. 수정 후 같은 실패 조건을 다시 실행하고 관련 정상 흐름을 확인한다. 불가능하면 미검증으로 남긴다.

## 판정

`통과`: 기재한 조건과 실제 결과가 맞음. `실패`: 관측 결과가 기대와 다름. `미검증`: 실행하지 못함. `해당 없음`: 기능·범위에 속하지 않음. 빌드, 단위 테스트, 실제 데이터 연결, 수동 UI 검증은 각각 기록한다. 제한된 표본을 전체 기능의 증명으로 확대하지 않는다.
