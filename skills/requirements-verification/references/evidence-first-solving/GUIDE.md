# 근거 기반 5단계 문제 해결

복잡한 과제에서 결과의 정확성과 누락을 확인하는 작업 절차다. 시험 규정·최신 공지·과제 지시가 우선이다. 내부 사고 과정이나 숨겨진 추론을 출력하라고 요구하지 않는다. 관찰 가능한 근거, 계산 과정, 선택 이유와 검증 결과만 필요한 만큼 제시한다. 단순한 작업에는 다섯 단계를 간단히 적용하고 형식적인 문서를 강제하지 않는다.

## 1. 추출: 무엇을 만족해야 하나

- 원문과 제공 파일에서 목표, 입력·출력, 필수 조건, 금지 사항, 제출 형식과 성공 기준을 추출하고 원문 위치를 붙인다. 확인된 사실, 가정, 미확정과 충돌을 분리한다.
- 결론에 영향을 주는 빠진 정보는 실무자에게 구체적으로 확인한다. 답이 없으면 영향을 기록하고 독립적으로 가능한 일부터 한다. 필수 조건을 임의로 선택 사항으로 바꾸지 않는다.

## 2. 풀이: 확인 가능한 작은 단위로 해결

- 요구에 맞는 접근을 선택하고 입력 → 처리 → 출력과 상태 변화를 정리한다. 계산 문제는 단위·공식·중간 결과를, 구현 문제는 입출력 계약·핵심 흐름·데이터 부작용을 확인한다.
- 필요한 자료와 환경을 실제로 확인한 뒤 처리한다. 외부 AI, 허용되지 않은 자동화·외부 전송·제한 우회는 사용하지 않는다. 작업 대상이 명확하면 구현까지 이어간다.

## 3. 검산·반론: 틀릴 수 있는 지점을 확인

- 요구의 독립적인 기준으로 핵심 결과를 재계산하거나 실행 결과를 대조한다. 입력의 누락·경계·단위, 실패 시 상태, 반례와 가장 영향 큰 대안 가정을 우선 점검한다.
- 코딩 과제라면 중요한 사용자 흐름과 정상·의미 있는 실패 조건을 실행하고 실제 관찰을 남긴다. 기존 실패를 수정했으면 같은 조건으로 다시 확인한다. 결과가 다르면 원인을 조사하고 수정 후 재검증한다.
- 검증을 수행하지 못하면 이유와 영향을 미검증으로 남긴다. mock과 실제 저장·연동, 코드 존재와 실행 성공을 구분한다. 근거 없는 검산 성공을 주장하지 않는다.

## 4. 산출물 초안: 결과와 근거를 연결

- 과제가 요구하는 파일·코드·보고서를 만든다. 채팅에는 필요에 따라 결론, 확인한 근거, 주요 계산·선택 이유, 남은 불확실성을 짧게 제시한다. 사용자가 요구한 결과 형식이 우선이다.
- 제출 전 구현 이해를 돕는 설명은 가능하되, 후속 서술형에서 AI 사용·답안 작성·복사 및 붙여넣기를 하지 않는다.

## 5. 요구사항 점검: 원문으로 돌아가기

- 각 필수 항목에 `원문 근거 → 결과물 위치 → 검증 방법과 관측 → 충족/실패/미검증`을 연결한다. 빠진 조건·형식·경계 사례를 수정하고 바뀐 부분을 재확인한다.
- 모든 필수 조건이 확인되지 않으면 완료라고 단정하지 않는다. 검증할 수 없는 것은 제한과 남은 조치를 밝힌다. 다수의 요구나 상태 전이는 `requirements-verification`, 오류 진단은 `verify-and-fix`를 읽는다.
