# 최소 PRD와 시스템 설계

원문·실제 데이터·담당자 답변을 근거로 필수 요구, 사용자 행동, 입력·출력, 업무 규칙, 가정·미확정을 연결한다. 시험이 지정한 문서·출력 양식은 그대로 따른다. 별도 상세 PRD가 필수가 아니면 처음에는 구현과 확인에 필요한 짧은 메모로 시작한다.

한 메모에 다음을 담는다: 필수 요구와 출처 / 입력과 결과 / 반드시 지킬 규칙 / 실제 질문·답변과 미확정 / 핵심 사용자 흐름 / 데이터·API·저장 상태 / 구현 순서 / 대표 검증. 요구 ID와 구현·검증 상태는 진행에 따라 연결한다.

기술은 제공 코드·런타임·오프라인 패키지 가용성·데이터 계산·실행·제출·경험·남은 시간으로 선택한다. Next.js를 기본 후보로 하되 과제에 맞지 않으면 다른 제공 환경을 선택한다. 설치 가능성과 성능을 확인 없이 사실로 말하지 않는다.

입력→화면→서버→검증·계산→저장→결과에서 필요한 경계만 둔다. 데이터의 최종 기준과 역할별 권한, 무효 입력·실패 시 이전 결과, 데이터 교체 및 실제로 중요한 중복·동시 요청을 정한다. 트랜잭션이나 버튼 차단만으로 모든 경합이 해결됐다고 가정하지 않는다.

필수 불변 조건과 품질·최적화 목표를 구분한다. 결과 검증의 기준 입력, 검사하는 항목과 한계를 정하고, 실제 선택한 대안·이유·비용을 짧게 기록한다. 원문에 없는 정책과 미확정 담당자 답변을 만들어 내지 않는다.
