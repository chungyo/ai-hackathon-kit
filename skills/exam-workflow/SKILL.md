# 시험 과제 진행

시험의 실제 안내·과제 원문·사용자 지시가 우선이다. 별도 폴더에 clone한 스킬이 자동으로 적용된다고 가정하지 않는다. 아래에서 현재 단계의 스킬만 실제 경로로 읽고, 이미 읽은 자료는 필요할 때만 다시 확인한다.

1. 원문·데이터·출력 계약·제출물·남은 시간·도구와 네트워크 제약을 확인한다. 응시자가 문제를 읽는 동안 AI는 허용 범위에서 요구·데이터·담당자 질문을 읽기 전용으로 분석할 수 있다.
2. 업무 정책의 불확실성은 실제 담당자에게 질문한다. 답변을 기다리며 영향받지 않는 작업을 진행한다. 대화·답변을 만들지 말고 출처·가정·영향을 기록한다.
3. 필수 요구와 설계·검증 기준을 정리한 뒤 practical-system-design의 handoff를 작성해 사용자가 검토하도록 한다. 사용자의 검토·구현 진행 의사가 명시되면 구현한다. 그 이후 기능마다 입력→처리→결과, 선택 이유, 실제 검증과 미확인을 간단히 설명하며 같은 승인을 반복하지 않는다.
4. 실제 필수 흐름과 중요한 실패·경계, 저장 상태 및 지정 제출물을 확인한다. 실제 실행·미실행과 실패·미검증을 분리한다. 필수 요구를 선택으로 낮추지 않는다.
5. 과제 풀이 중 사용자가 실제 코드와 증거로 설명할 수 있게 돕는다. 후속 서술형에서의 AI·자료 사용은 실제 시험 규정이 우선이다.

## 단계별 선택

| 단계 | 스킬 |
| --- | --- |
| 문제·데이터·담당자 질문 | discover-and-decide |
| 최소 PRD·기술·시스템 설계 | practical-system-design |
| 실제 기능 구현 | build-small |
| 데이터·결과·요구 검증 | requirements-verification |
| 과제 중 이해·제출 전 설명 | explain-my-work |

3시간 과제의 예시 배분은 분석 15분, PRD·설계 20분, 구현과 단계별 확인 110분, 통합 검증 25분, 제출 확인 10분이다. 강제 타이머가 아니며 실제 난이도·남은 시간에 맞춰 조정한다. 초반부터 필수 실행과 검증 시간을 남긴다.

별도 세션·병렬 에이전트·브라우저 자동화·패키지 설치는 실제 시험에서 허용되고 가능한 경우만 사용한다. 독립적인 사람/AI 작업은 겹치되 미확정 정책과 같은 파일·DB를 동시에 변경하지 않는다. 오프라인일 때 외부 접근을 우회하지 않는다.
