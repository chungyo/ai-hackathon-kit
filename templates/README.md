# 실전 작업 템플릿

처음 보는 과제에서 요구사항을 파악하고 구현·검증·설명까지 연결하기 위한 도구다. 템플릿은 연습용이며 실제 시험에 반입하거나 사용해도 된다는 뜻이 아니다. 최신 운영 공지, 시험 환경의 허용 범위, 실제 과제 지시가 항상 우선한다. 특히 도구 사용, 자료 반입·열람, 후속 서술형의 AI·복사 사용 허용 여부를 확인한다.

## 구성

- [WORKBOOK.md](WORKBOOK.md): 과제마다 복사해서 채우는 통합 작업판. 요구 → 구현 → 검증의 기준 문서.
- [PROMPTS.md](PROMPTS.md): 분석, 설계, 구현, 테스트, 설명을 위한 단계별 AI 지시문.
- [DESIGN_PRACTICE.md](DESIGN_PRACTICE.md): PRD에서 상태·데이터·실패·동시성·검증 설계로 이어지는 학습 예시.
- [EXAM_PLAYBOOK.md](EXAM_PLAYBOOK.md): 문제를 받은 순간부터 제출까지의 실전 절차와 기술 스택 선택 기준.
- [EXAM_SEQUENCE.md](EXAM_SEQUENCE.md): 시간순으로 바로 적용할 프롬프트·템플릿과 사람/AI 병렬 작업표.
- 더 상세한 분석이 필요할 때만 [PRD 양식](../skills/practical-system-design/references/practical-prd/references/PRD_WORKSHEET.md), [검증 작업표](../skills/requirements-verification/references/ACCEPTANCE.md)를 참고한다.

## 사용 순서

1. 시험 규정, 과제 지시, 제공 파일과 기존 작업 상태를 확인한다. 덮어쓰면 안 되는 파일과 필수 제출물을 먼저 적는다.
2. 허용된 경우 작업판을 과제에 맞는 새 파일로 복사한다. 과제에서 필수 문서의 이름·양식을 정했다면 그 지시가 우선이며, 작업판은 이를 대체하지 않는다. 별도 파일이 허용되지 않거나 시간이 부족하면 표의 핵심만 메모한다.
3. `0~2`를 빠르게 채운 뒤 실무자에게 구현에 영향을 주는 질문을 한다. 답변을 기다리는 동안 영향을 받지 않는 작업을 진행한다.
4. `3~4`에서 기술과 구현 순서를 정한다. 한 번에 모든 기능을 만들지 않고 필수 사용자 흐름 하나를 입력 → 처리 → 출력까지 연결한다.
5. 변경을 검증할 때마다 `5~6`에 **실제 실행한 방법과 관측 결과**를 적는다. 구현·테스트·실제 연결·수동 확인은 별개다.
6. 마지막에 `7~8`로 제출물과 설명 가능 여부를 확인한다. 후속 서술형에서 AI나 복사가 금지되면 본인의 이해를 바탕으로 직접 작성한다.

작업판은 한 번에 다 채우는 문서가 아니다. 문제를 읽으면서 요구와 질문을 적고, 구현·검증할 때 해당 행을 갱신한다. 시험장에서 모든 상세 항목을 새로 작성할 필요는 없다.

## 3시간 과제의 출발점

| 구간 | 권장 | 목표 |
| --- | --- | --- |
| 문제·계약 파악 및 질문 | 20~25분 | 필수 조건, 제출물, 불명확한 정책 정리 |
| 간단한 PRD·설계 | 10~15분 | 핵심 흐름, 결정, 검증 기준 정리 |
| 작은 단위의 구현과 즉시 검증 | 95~105분 | 필수 흐름부터 실제 연결 |
| 전체 요구 대조·제출 준비 | 35~40분 | 실제 실행, 제출물과 미검증 정리 |

총 160~185분인 선택 범위이므로 실제로는 **남은 시간을 확인하며 합계가 제한 시간 이내가 되도록 조정**한다. 예: 20 + 10 + 100 + 35 = 165분, 나머지 15분은 질문 대기·문제 해결 여유다. 구현 중에도 테스트한다. 시간 부족은 필수 요구사항을 선택 사항으로 바꾸는 근거가 아니다.

## 짧은 작업 예시

가상의 요구가 “담당자가 유효한 데이터를 등록하면 저장하고 다시 조회한다”라면:

| 요구 | 인수 기준 | 작업 | 검증 |
| --- | --- | --- | --- |
| R1 데이터 등록 | 유효한 데이터가 저장된다 | 입력 검증 → 저장 API | 유효 입력 후 실제 저장 확인 |
| R2 결과 재조회 | 저장된 데이터를 다시 읽을 수 있다 | 조회 API → 결과 화면 | 별도 요청으로 저장 값과 응답 비교 |
| Q1 | 무효 데이터가 섞인 경우의 처리 정책 | 담당자에게 질문 | 답변 전 기대 결과를 확정하지 않음 |

예시는 형식을 설명할 뿐 실제 과제의 정책이나 결과가 아니다.
